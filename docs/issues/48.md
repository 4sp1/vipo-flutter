# macOS cannot reach the vipo-go server (localhost:8080)

## Problem

The app's API base URL defaults to `http://localhost:8080` (`lib/data/api_config.dart`), and `AppDeps` (`lib/di.dart`) wires the generated `LogsApi`/`NotesApi` with a `Dio` configured against it. This matches the vipo-go backend at `127.0.0.1:8080` and works on iOS, where ATS (App Transport Security) is not enforced for loopback connections.

On macOS, however, outgoing network requests are silently blocked at the sandbox level:

- `macos/Runner/DebugProfile.entitlements` declares only `com.apple.security.network.server` (inbound connections for the debug VM service) but **not** `com.apple.security.network.client` (outbound connections).
- `macos/Runner/Release.entitlements` declares **no network entitlement at all**.

Result: every HTTP call to the vipo-go server fails. Dio surfaces errors (e.g. `Connection refused`/socket errors) even while the server is running, because the sandbox drops the outbound socket before any connection attempt is made.

## Fix

Add the outbound-network entitlement to **both** macOS entitlements files:

```xml
<key>com.apple.security.network.client</key>
<true/>
```

Files:

- `macos/Runner/DebugProfile.entitlements`
- `macos/Runner/Release.entitlements`

No changes are needed to `Info.plist` (ATS does not apply to loopback) or to Dart code — the base URL and wiring are already correct.

## Notes

- Keep `com.apple.security.network.server` in `DebugProfile.entitlements`: it backs the Flutter debug tooling (`dart vm_service`), not app networking.
- Production deployments talk to a remote HTTPS endpoint (override via `flutter run --dart-define=API_BASE_URL=https://api.example`); the outbound entitlement is required either way.
- Verify with `flutter run -d macos` against a local vipo-go instance at `127.0.0.1:8080`: observe logs/notes fetches succeed and a created note appears on a restart-free round trip.
